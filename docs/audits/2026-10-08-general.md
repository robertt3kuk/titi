# titi audit — 2026-10-08 — general (areas 1, 2, 5, 6, 7, 8, 9, 10)

Read-only audit of `master` @ `3aa6774`. Evidence is code at the cited lines
plus CI: `gh run list --repo robertt3kuk/titi --branch master --limit 10` (all
success) and the clippy job log of run `37267636467`. Nothing was built or
re-run locally. Sections 3 (secrets) and 4 (tools/approval, traversal) are
handed to the security audit — not examined here.

## Summary

1. The engine boundary holds: `titi-tui` has no provider/HTTP dependency at
   all, and `titi-cli` reaches models only through `EngineCommand`/`EngineEvent`.
2. But the workspace's own error lints are inert for 8 of 11 crates, so
   AGENTS.md's "no `unwrap`/`expect`/`panic!` outside tests" is enforced only in
   `titi-engine`, `titi-providers` and `titi-genome`.
3. Persistence is the weakest area: no `fsync` anywhere in `titi-core`, three
   in-place truncating rewrites, and an `fd-lock` helper that runs the guarded
   write after a failed acquire and then unlinks the lock file.
4. Providers are safe on retry semantics (401/unknown-model never retried,
   retry only before the first visible token), but the advertised first-event /
   idle watchdogs are dead config, so a provider that opens a socket and then
   stalls hangs the turn forever and `Cancel` cannot unblock it.
5. Two test-hygiene landmines: `cargo test -p titi-cli` deletes the developer's
   real stored provider key (`chat.rs:10969` via `/logout openai`), and a whole
   second TUI (`titi_cli::app::App`, 2492 lines) is unreachable from the shipped
   binary but carries five integration test files, so part of the TUI suite
   asserts the behaviour of code users never run.

## Findings

### Critical

None. Nothing here loses data in normal operation or crosses a trust boundary
(the latter is the security auditor's section).

### High

- **[high] (area 2) The workspace error lints are silent in 8 of 11 crates** —
  `Cargo.toml:38-43` declares `unsafe_code = "forbid"`, `unwrap_used = "warn"`,
  `expect_used = "warn"`, but only `crates/titi-engine/Cargo.toml:7`,
  `crates/titi-providers/Cargo.toml:7` and `crates/titi-genome/Cargo.toml:7`
  carry `[lints] workspace = true`; `titi-cli`, `titi-core`, `titi-config`,
  `titi-memory`, `titi-secrets`, `titi-soul`, `titi-tools` and `titi-tui` do
  not, so those lints never run on them (CI run `37267636467` reported
  `unwrap_used`/`expect_used` 403 times in `titi-engine` and 180 in
  `titi-providers`, and zero in the other eight). AGENTS.md:64-65 states the
  rule these lints were supposed to enforce, so today the rule is a convention
  the largest crate (`titi-cli`, 14k-line `chat.rs`) does not even lint for.
  *Fix:* add `[lints]\nworkspace = true` to the eight manifests. Expect one
  real cost: `unsafe_code = "forbid"` cannot be relaxed by an inner `allow`, so
  `crates/titi-cli/tests/login_oauth.rs:416,430` (`unsafe { env::set_var }`)
  needs a rewrite (drive the child process, or set the var via
  `Command::env`) before `titi-cli` can opt in.

- **[high] (area 6) Session files are written without `fsync` and rewritten in
  place** — `crates/titi-core/src/session/store.rs:102-107` appends with
  `writeln!` and no `sync_all`; `store.rs:262` rewrites the whole session file
  with `fs::write` (`truncate(true)`) inside `rewind`, and the same pattern
  rewrites the checkpoint sidecar at `store.rs:281`, and `record_git_commit`
  (`store.rs:199-216`) rewrites it again in place at `store.rs:215` to attach a
  commit. `grep sync_all crates/titi-core` finds nothing, so a crash
  (or power cut) during any of these aborts the session file to whatever
  survived; the crash between the append and `set_leaf` (`store.rs:108`) leaves
  the new entry orphaned. The repo already knows the safe pattern — the only
  fsync in the workspace is `crates/titi-memory/src/store.rs:291-304` (tmp →
  `sync_all` → `rename`). *Fix:* reuse that pattern for `rewind`, the checkpoint
  sidecar and `record_git_commit`, and `sync_all` after the append in
  `append_entry`.

- **[high] (area 6) The `fd-lock` helper runs the guarded write after a failed
  acquire, then unlinks the lock file** — `crates/titi-config/src/config_file.rs:176-185`:
  `match guard.write() { Ok(_w) => f(), Err(_) => f() }` and `Err(_) => f()` for
  the open failure, followed by `let _ = fs::remove_file(&lock_path);` at
  `:183`. The two `f()` fallbacks make the lock advisory in name only (the whole
  point of `settings.rs:370,385` taking it is to serialise overlapping writers),
  and unlinking a held lock file lets a third writer create a fresh inode that a
  second writer can lock concurrently. *Fix:* never delete the lock file, and
  make both error arms bounded-retry-then-`Err` — `f()` must not run unguarded.

- **[high] (area 5) A stalled provider hangs the turn forever and `Cancel`
  cannot unblock it** — `WatchdogConfig` declares `first_event_timeout: 120s`
  and `idle_timeout: 60s` (`crates/titi-providers/src/transport.rs:190-212`) and
  `mock.rs:144-149` sets them to 100ms, but the only field any production code
  reads is `post_finish_grace` (`crates/titi-providers/src/wire.rs:967-968`), and
  even that timeout wraps a read only once a terminal event is held
  (`wire.rs:770-777`); the ordinary read is a bare `state.body.next().await`
  (`wire.rs:776`). `ReqwestFetch::new` builds the client with no `.timeout()`
  (`crates/titi-providers/src/http.rs:53-55`), and the abort flag is only polled
  between stream events (`crates/titi-engine/src/runtime.rs:2163-2165,2183-2185`)
  — the engine's own comment admits the hole at `runtime.rs:2159-2162`
  ("a cancel that lands after `stream` was called hits a request already in
  flight"). So a server that completes the TCP/TLS handshake and then sends
  nothing wedges the turn indefinitely; Ctrl+C sets a flag nothing reads, and
  `TransportError::Stalled` (`transport.rs:138-139`, retryable per
  `transport.rs:147-155`) is produced by tests only.
  *Fix:* wrap each `body.next().await` in the watchdog timeouts, and race the
  abort flag with the stream (`futures::stream::select` with a poll-stream that
  ends on `aborted`) so both the hang and the cancel resolve.

- **[high] (area 1/8) `titi_cli::app::App` is unreachable from the shipped
  binary and is kept alive by the test suite** — `crates/titi-cli/src/main.rs:334`
  runs `titi_cli::chat::run(engine, …)`, and `chat.rs` contains zero references
  to `App`; the only construction sites are
  `crates/titi-cli/tests/dispatch.rs:10`, `tests/checkpoints.rs:18`,
  `tests/overlays_paste.rs:25`, `tests/engine_events.rs:9`,
  `tests/transcript.rs:21,51,73,101`. `crates/titi-cli/src/app.rs:1-4` still
  claims "the binary wraps it with crossterm raw mode + alternate screen",
  which is false today. Consequences: 2492 lines of duplicate UI logic
  (including the `/mouse` preset at `app.rs:1836-1846`, a feature the shipped
  screen documents as unsupported at `README.md:108` and `main.rs:23`), 16 of the
  97 `Result<…, String>` APIs, and roughly 1650 lines of integration tests whose
  subject is not the product's behaviour. *Fix:* decide — wire `App` in and
  delete `Chat`, or delete `app.rs` and the five test files with it; leaving both
  makes the TUI test suite misleading.

- **[high] (area 8) A test signs the developer out of their real provider
  account** — `crates/titi-cli/src/chat.rs:10969`
  (`guard_every_listed_command_dispatches_and_does_something`) builds its chat
  with the bare helper (`chat.rs:7295-7299`), which leaves `agent_dir` at the
  default from `Chat::new` — `chat.rs:539`
  `agent_dir: titi_config::agent_dir()`, the real `~/.titi/agent` — then loops
  over every listed command (`chat.rs:11015`) passing `"openai"` to `/logout`
  (`chat.rs:11022`). `logout` (`chat.rs:2531-2554`) calls
  `crate::secrets::remove_key(&self.agent_dir, provider)` after a name check
  only (`chat.rs:2565-2569` accepts `openai`), and `remove_key`
  (`crates/titi-cli/src/secrets.rs:57`) opens `agent_dir/auth.db` and deletes the
  row. Running `cargo test -p titi-cli` on a machine with a stored OpenAI key
  therefore destroys it — this workstation has a 20 KB
  `~/.titi/agent/auth.db` — and CI cannot catch it because its HOME has none.
  The same loop reaches the real agent dir through `/export path.md`
  (`chat.rs:1440` → `app::export_session`, `crates/titi-cli/src/app.rs:2259-2287`,
  which opens the real `state.db` and writes to a CWD-relative path) and
  `/checkpoint`. The correct pattern is one screenshot away:
  `logout_forgets_the_stored_key` (`chat.rs:11753-11768`) builds the same chat on
  a `TempDir` and assigns `chat.agent_dir`. *Fix:* build the guard test's chat
  from `picker_chat(...)` (`chat.rs:7328-7333`); the guard is about dispatch
  coverage, not about the store.

### Medium

- **[medium] (area 10) The README slash table is wrong in three ways** —
  `/skillful` is documented (`README.md:99`, `README.md:303`) and exists nowhere
  in the repository (`grep -rn skillful --include=*.rs .` → no hits);
  `README.md:174` and `:378` say the council is "an engine command today
  (`RunCouncil`), with no slash command in front of it yet" while
  `crates/titi-cli/src/chat.rs:1275` dispatches `council` and `chat.rs:3512`
  lists it in the command table (the same is true of `/graph`,
  `chat.rs:1276,3516`); and `/genome` (`chat.rs:1278,3436`) and `/git`
  (`chat.rs:1287,3520`) are in the shipped table but absent from the README.
  *Fix:* regenerate the README table from `chat.rs:3378-3527`.

- **[medium] (area 2) Stringly-typed and silently discarded errors at the CLI
  boundary** — 97 fallible `src` APIs return `Result<…, String>`
  (16 in `app.rs`, 10 in `files/titi-tools/src/fs.rs`, 10 in `login.rs`,
  6 in `session_log.rs`, 6 in `chat.rs`), 33 sites collapse a typed error with
  `map_err(|e| e.to_string())`, and `crates/titi-cli/src/session_log.rs:25`
  returns `Option<Self>` from `open`, so a session log that cannot be created is
  indistinguishable from one that is not wanted. Headless then discards every
  write failure: `crates/titi-cli/src/headless.rs:198,227,252,292,314,336` are
  `let _ = log.user(...)` / `let _ = log.assistant(...)`, and
  `headless.rs:218,270,329` emit
  `serde_json::to_string(&event).unwrap_or_default()`, which puts a blank line
  into the documented JSONL protocol stream (`README.md:58`) instead of failing.
  *Fix:* `SessionLog::open -> Result<SessionLog, SessionError>`, keep the typed
  error at the CLI seam, and make the JSONL writer a hard error (or an
  `EngineEvent` error frame) rather than an empty line.

- **[medium] (area 5) A retry can duplicate thinking output** —
  `is_content()` counts only `TextDelta | ToolcallDelta`
  (`crates/titi-providers/src/stream.rs:140-148`), so a stream that emitted
  `ThinkingDelta` and then failed with a retryable error is retried
  (`runtime.rs:2002-2005` gate sees `visible_content == false`), replaying the
  thought deltas to the event consumer a second time. No answer text is
  duplicated. *Fix:* treat a non-empty thinking buffer as visible content, or
  clear the thinking block before the retry. [INFERENCE: whether the TUI paints
  the duplicate was not traced.]

- **[medium] (area 5) `fallback_chain` / `fallback_cooldown` are dead config** —
  `crates/titi-engine/src/runtime.rs:489-491` declares both and `:530-533`
  initialises them, `crates/titi-config/src/fallback.rs:46-49` parses
  `fallback.chains`/`cooldownSecs`, and nothing in the workspace ever calls
  `FallbackChain::select` (repo-wide grep: definition, unit tests, and the
  `EngineConfig` field only). Every turn therefore re-walks the static
  `fallback_models` list from the primary, ignoring configured cooldowns and
  role chains. *Fix:* call `select()` in the model loop, or delete the field and
  the config keys.

- **[medium] (area 8) Wall-clock assertions that can flake and one that asserts
  nothing about the product** — `crates/titi-cli/tests/first_frame.rs:58`
  asserts `ttff < 150ms` for an in-memory render on a shared CI runner, and
  `:79-82` asserts `init_elapsed >= 1500ms`, which only re-measures the test
  fixture's own 2s `thread::sleep` (`:27-30`, poll loop `:75-77`). Same shape in
  `crates/titi-tools/src/pipe.rs:306` and `crates/titi-tools/src/pty.rs:423`
  (1.2s sleep before asserting a killed child's output stopped) and
  `crates/titi-engine/tests/tools.rs:953` (300ms sleep to let a shell trap
  install). None has flaked in the last 10 CI runs, but each is a timing
  assumption, not a contract. *Fix:* inject a clock where the code already
  supports one (`crates/titi-cli/src/app.rs:1368`), wait on a file/event
  rather than a duration elsewhere, and drop the `>= 1500ms` assertion.

- **[medium] (area 8) The default test chat is not isolated, and the suite
  relies on it being harmless** — `crates/titi-cli/src/chat.rs:539` sets
  `agent_dir: titi_config::agent_dir()` (`~/.titi/agent`) in `Chat::new`, and the
  bare helper `fn chat()` (`chat.rs:7295-7299`) does not override it; 136 tests
  in the module build on that helper. Individually they are fine (I checked each
  one that mentions `agent_dir` and each one that dispatches a slash command:
  none reads the real directory without overriding it — only the guard test
  below does, indirectly), but the isolation is accidental rather than
  structural: any new test that reaches a settings, theme or skill load through
  the helper runs against whatever is on the machine. *Fix:* make the bare helper
  take a `TempDir` the way `picker_chat` does (`chat.rs:7328-7333`); the rest of
  the suite already uses tempdirs plus `TITI_AGENT_DIR` (e.g.
  `crates/titi-cli/tests/headless.rs:62`).

- **[medium] (area 7) A panic while the screen is owned destroys its own
  message** — the default panic hook writes to stderr while the process is still
  in the alternate screen with raw mode on; `Screen::Drop`
  (`crates/titi-cli/src/chat.rs:3362-3370`) then leaves the alternate screen,
  erasing exactly the text that explained the crash. There is no
  `std::panic::set_hook` anywhere in the workspace (repo-wide grep: none).
  Terminal *state* is restored correctly (raw mode off, cursor shown, alt screen
  left) and there is no `panic = "abort"` in `Cargo.toml:45-47`, so unwinding
  does run `Drop`. *Fix:* install a hook that leaves the alternate screen first
  and then prints the message and location.

- **[medium] (area 8) The headless wire protocol is serde-tested on exactly one
  sample** — `crates/titi-cli/tests/headless.rs:8-20` round-trips one
  `EngineEvent` and one `EngineCommand`; the framing/version behaviour is
  covered (`headless.rs:24-55`), but nothing checks that every variant
  (`EngineEvent`, `crates/titi-engine/src/protocol.rs:161+`) survives a JSON
  cycle, and neither enum is `#[non_exhaustive]` (grep: 0). A rename or a new
  required field in `protocol.rs` ships as a silent break of the public JSONL
  surface documented in `README.md:58`. *Fix:* a table-driven round-trip over
  all variants plus an unknown-field tolerance case.

### Low

- **[low] (area 9) Five direct dependencies are unused or over-declared** —
  `crates/titi-tui/Cargo.toml:8` (`titi-core`) and `:13` (`crossterm`) are
  referenced nowhere in `titi-tui`'s `src/` or `tests/`; `crates/titi-tools/Cargo.toml:17`
  (`titi-config`) and `crates/titi-core/Cargo.toml:10` (`titi-tools`) likewise;
  `crates/titi-cli/Cargo.toml:25` declares `tempfile` as a runtime dependency
  while all 39 uses are inside `#[cfg(test)]` modules, and it is declared a
  second time as a dev-dependency at `:29`. *Fix:* delete the four unused lines
  and move `tempfile` out of `[dependencies]`.

- **[low] (area 2) A blanket lint allow hides `expect` in the genome parser** —
  `crates/titi-genome/src/parse.rs:3` is `#![allow(clippy::expect_used)]` for
  the whole module (a rationale comment sits above it, `parse.rs:1-2`), which is
  why the 21 `Regex::new(...).expect(...)` calls (e.g. `parse.rs:438-442`) do
  not appear in the CI clippy counts even though `titi-genome` opts into the
  workspace lints. Most are static patterns where the failure is impossible, but
  a module-wide allow cannot tell those from the one that is not:
  `parse.rs:553` (`Regex::new(exports_pattern).expect("caller-supplied export pattern")`).
  *Fix:* scope the allow to the `LazyLock` items and make the caller-supplied
  pattern return an error. [Note: `parse.rs` and `symbols.rs` were being edited
  by a concurrent worker while this audit ran; the allow was still module-wide at
  the revision read.]

- **[low] (area 6) The lenient JSONL reader launders mid-file corruption into
  missing entries** — `crates/titi-core/src/session/store.rs:434-438` skips any
  line that fails to parse, with a comment that argues only for tolerating a
  torn *final* line; `walk` (`store.rs:141-166`) then silently breaks the parent
  chain and `checkpoints` (`store.rs:219-235`) does the same for the sidecar, so
  a flipped bit in the middle of a session removes an entry with no signal.
  *Fix:* be lenient only on the last line and return a `Corrupt` error
  otherwise, so a surface can offer a rewind instead of a silent gap.

- **[low] (area 6) No schema version anywhere** — the session index migrates by
  `PRAGMA table_info` + `ALTER TABLE` (`crates/titi-core/src/session/index.rs:71-88`);
  `crates/titi-secrets/src/store.rs:219-234` opens `auth.db` and migrates with
  no `journal_mode`, `busy_timeout` or `foreign_keys` set (the session index
  sets WAL + `busy_timeout=5000` at `session/index.rs:60`);
  `crates/titi-memory/src/index.rs:106-108` sets WAL/foreign keys but no
  `busy_timeout`. Nothing records `PRAGMA user_version`, and the file format has
  no version field, so a future destructive change has no hook. *Fix:* set
  `user_version` in all three stores and add a version tag to the session entry.

- **[low] (area 10) The README's local verify commands are weaker than CI** —
  `README.md:205-208` (and `:409-412`) list `cargo fmt --check`,
  `cargo clippy -p titi-engine --all-targets`, `cargo test --workspace`, while
  AGENTS.md:44-46 and `.github/workflows/ci.yml:24,34,42` run
  `--all --check`, `--workspace --all-targets` and `--workspace --locked`. A
  contributor following the README lints one crate and skips the lock check.
  *Fix:* copy the AGENTS.md block.

- **[low] (area 1/8) The boundary is guarded by a manifest substring test** —
  `crates/titi-tui/tests/dependency_rule.rs:14-27` asserts only that
  `titi-tui`'s `Cargo.toml` does not contain the strings `titi-providers` /
  `titi-tools`. It cannot catch a new transitive path to a provider (or a
  reintroduced `reqwest`), and `titi-tui`'s declared-but-unused `titi-core`
  (`Cargo.toml:8`) shows the manifest is already not trustworthy as a spec.
  *Fix:* assert on the resolved graph (`cargo metadata` output) or, cheaper,
  keep the manifest check and extend it to `reqwest`/`hyper`/`titi-engine`.

## Tech debt not worth fixing now

- `WatchdogConfig::empty_completion_retries` / `empty_completion_backoff`
  (`crates/titi-providers/src/transport.rs:197-199`) have no consumer; an empty
  completion is treated as success (`runtime.rs:1955-1963`). Remove the fields or
  wire them, but they are harmless while the first-event hole above is open.
- Duplicate transitive versions in `Cargo.lock` (`getrandom` ×3, `syn` ×3,
  `thiserror` 1+2, `hashbrown` ×3, `bitflags`, `rand`, `windows-sys`, `termios`)
  are the resolver's business, not hand-managed here.
- Neither `EngineCommand` nor `EngineEvent` is `#[non_exhaustive]`
  (`crates/titi-engine/src/protocol.rs:58,161`); the `"v"` framing already covers
  the client-visible case.
- `crates/titi-cli/src/herdr.rs:119-123` asserts
  `Reporter::from_env().is_none() || env::var("HERDR_ENV").is_ok()`, which is
  only meaningful on a machine that is not a Herdr pane; and `crates/titi-cli/tests/session_log.rs:144` pins the
  `MAX_RESTORED_MESSAGES == 40` literal (behaviour is covered at `:197-219`).
- Images are only drawn on kitty/ghostty with no picture fallback
  (`crates/titi-cli/src/chat.rs:6169`), but that *is* the documented contract
  (`README.md:110`: "Other terminals leave the path as text"), so it is not a
  defect. `docs/QA_STATUS.md:34` still records local photos as "unverified".
- The retry backoff slices a sleep in 50ms steps to stay cancel-aware
  (`runtime.rs:2064-2077`) — fine, but the surrounding read loop is not, so this
  only half-delivers the property it is there for.
