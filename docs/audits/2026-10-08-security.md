# Security audit — items 3 (secrets) and 4 (tools/approval) + the new toolbox

Auditor: `audit-security` (read-only; one file written: this one).
Scope: AUDIT_PROMPT.md items 3 and 4, plus `titi-engine/src/difftrack.rs`,
the genome prompt projection, and the genome LSP server.
Every claim below is traced to a `file:line`. Regex claims were checked by a
byte-for-byte transcription of the Rust pattern into Python (noted per case) —
no `cargo test` was run (audit rules), so the regex-crate specifics are
[INFERENCE] where they need a live engine.

## Summary (5 lines max)

- Item 4 is in good shape: one enforcement point (`tool_loop.rs:328-329`), the
  workspace jail is real (`fs.rs:26-63`), `yolo` skips only the prompt, and the
  settings guard is case-insensitive and prefix-aware.
- Item 3 holds at rest (0600 `auth.db`, masked `Debug`, masked provider errors,
  masked sessions/casts) but leaks on two of the four egresses: the diff
  snapshot to the prompt and raw tool args to `trajectories/*.jsonl`.
- `difftrack`'s secret filter is materially weaker than `SensitivePolicy`, and
  `redact`'s generic pattern misses quoted/JSON and `_`-suffixed key names —
  the two together let a private key or `AWS_SECRET_ACCESS_KEY` reach the model.
- A cloned repo's `.env` outranks the user's own credential layers, unlike every
  other protected setting.
- The genome LSP cannot be pointed outside its root and serves only the index;
  no finding beyond a low prompt-injection gap in the `<diff>` frame.

## Findings

### [high] The `git diff HEAD` prompt block leaks credential files the read tools refuse — `crates/titi-engine/src/difftrack.rs:279-288` (+ `:146-148`, `crates/titi-engine/src/runtime.rs:179-209,1800,1816`)
`is_secret_path` keeps only `.env`, `.env.*`, `*.pem`, `*.key` by basename, and
`line_has_secret` (`:295-313`) only fires on `api_key|api-key|apikey|secret|token|password`
followed by `:`/`=`. `assemble:146-148` therefore keeps any other section, and
`capture()`'s text is wrapped in `<diff>` (`runtime.rs:204-209`) and appended to
the user prompt (`runtime.rs:1816`) with **no** redaction pass.
Concrete path: a repo with a tracked, modified `fixtures/service-account.json`
(Google service account, real `private_key`), `id_rsa`, `config/credentials.json`,
`.aws/credentials`, `terraform.tfstate` or `*.p12` → `git diff HEAD` →
section survives → the private key is sent to the provider, while `read`/`grep`
on the same path are refused by `SensitivePolicy` (`titi-tools/src/sensitive.rs:11-53`,
wired at `titi-cli/src/engine.rs:673-678`). Transcription of the exact Rust
scan confirms: `is_secret_path("id_rsa")==false`, `is_secret_path(".aws/credentials")==false`,
`is_secret_path("fixtures/service-account.json")==false`,
`line_has_secret('+  "private_key": "-----BEGIN PRIVATE KEY-----",')==false`,
`line_has_secret("+-----BEGIN OPENSSH PRIVATE KEY-----")==false`.
Fix: hand `SensitivePolicy` into `capture`/`assemble` and drop any section whose
path `blocks()` (one list, not two), and run the assembled text through
`titi_memory::redact::redact` as a second line.

### [high] Tool-output/memory masking misses the most common key spellings — `crates/titi-memory/src/redact.rs:349-370`
The catch-all pattern is
`(?i)\b(?:api[_-]?key|token|secret|password|passwd)\b\s*[:=]\s*['"]?[A-Za-z0-9_\-\./+]{12,}`.
Two holes: (1) the closing `\b` cannot cross `_`, so suffix-style names
(`AWS_SECRET_ACCESS_KEY=`, `DB_PASSWORD=`, `NPM_TOKEN=`, `client_secret:`) never
match; (2) a quote between the name and the `:`/`=` breaks `\s*[:=]`, so
`{"api_key": "…"}`, `{"token":"…"}`, `"client_secret": "…"` never match.
Transcription result (value `abcdefghijklmnopqrstuvwxyz123456`, no provider prefix):
`{"api_key": "…"}` LEAKED, `{"token": "…"}` LEAKED, `{"secret": "…"}` LEAKED,
`client_secret: …` LEAKED, `AWS_SECRET_ACCESS_KEY=…` LEAKED,
`Authorization: Bearer …` LEAKED.
Concrete path: `mask()` (`titi-engine/src/tool_loop.rs:280-285`) is the only pass
on tool output; the bash child inherits the whole process env
(`titi-tools/src/pipe.rs:81-85`, `pty.rs:225-227`; `load_into` is never called —
`titi-secrets/src/env.rs:55-65,76-77` has no non-test caller). An approved `bash env`
(or `read` of a JSON/YAML config with a base64 value) therefore prints
`DB_PASSWORD=…` into the provider request *and* the session file, and
`remember` (`titi-memory/src/tool.rs:115-119`) persists it the same way.
Fix: drop the trailing `\b` and allow a closing quote —
`(?i)[A-Za-z0-9_]*[_-]?(?:api[_-]?key|token|secret|password|passwd)\b['"]?\s*[:=]\s*['"]?[A-Za-z0-9_\-\./+]{12,}`
— and add a `(?i)bearer\s+[A-Za-z0-9_\-\.]{20,}` pattern; re-check `MARKERS`
(`:380-400`) still prefilters every new pattern.

### [medium] Raw tool arguments are persisted unmasked in the trajectory file — `crates/titi-engine/src/tool_loop.rs:167-171` (+ `crates/titi-core/src/trajectory.rs:99-107`)
`EventKind::ToolCall { args: args.clone() }` is recorded before any masking,
while the *result* is masked two blocks later (`tool_loop.rs:222-229`). The file
is `<agent_dir>/trajectories/<session>.jsonl` (`trajectory.rs:100-102`), created
with default permissions — no `0600` (contrast `titi-secrets/src/store.rs:226-229`).
Concrete path: the user pastes a key and the model calls `memory`/`write` with
it (or a `bash` command embeds one) → the raw JSON is persisted, defeating the
stated invariant "a key or a server address the tool printed stops here"
(`tool_loop.rs:217-221`; `redact.rs:1-6`).
Fix: redact string values inside `args` before `record`, and open the file 0600.

### [medium] A cloned repository's `.env` outranks the user's own credential layers — `crates/titi-secrets/src/env.rs:37-48` (+ `crates/titi-engine/src/registry.rs:163-164,306-310`)
Resolution order is process env → `<cwd>/.env` → `<agent_dir>/.env` → `auth.db`
(`env.rs:37-41` `layer_files`). Every other trust decision reads *past* the
project layer on purpose (`Settings::get_user`, `titi-config/src/settings.rs:219-232`;
used at `titi-cli/src/engine.rs:387-389`, `:487-494`), but this one does not.
Concrete path: `git clone <hostile> && titi` → the repo's `.env` supplies, empties
or replaces `OPENAI_API_KEY`/`ANTHROPIC_API_KEY` for every turn; the user's
stored key is silently shadowed and a bad value breaks every turn. (The user's
key is not read out — substitution, not exfiltration.)
Fix: resolve the project `.env` only for keys the agent layer does not define,
or drop the project layer for `credential_env` lookups.

### [low] `write` can plant code that runs outside the approval tier later — `crates/titi-tools/src/fs.rs:469`
`WriteFileTool::invoke` uses `jail_path` only, with no `SensitivePolicy`, and
`.git` sits inside the jail (nothing in `fs.rs:26-45` excludes it). A Write-tier
call (auto-approved under `--approval yolo`) can create `.git/hooks/pre-commit`
or edit `.git/config` (`core.hooksPath`, `core.fsmonitor`, aliases), which the
user's next git command — including titi's own `git_commit`
(`crates/titi-tools/src/git.rs:196`) — then executes.
Fix: refuse `.git/` (and any directory git consults) in `jail_path` for
write/edit, or add it to the sensitive defaults.

### [low] The `<diff>` frame around the snapshot is not sanitised — `crates/titi-engine/src/runtime.rs:204-209` (+ `crates/titi-engine/src/difftrack.rs:152-158,168-183`)
`bound_text`/`assemble` copy git's `diff --git a/<name> b/<name>` header verbatim
into the prompt text, and `render_diff` wraps it in `<diff>…</diff>` with no
angle-bracket or control-character filtering — unlike the genome, which drops
such paths (`titi-genome/src/project.rs:22-23`) and skips control-char names
(`titi-genome/src/scan.rs:107-108`). A tracked, modified file whose *name*
contains `</diff>` puts a forged close of the frame in front of the model
(git emits the bytes whether or not it quotes the path — `take_quoted`
decodes escapes but the raw header is copied). Prompt-injection only; the same
repo content is already reachable through `read`.
Fix: replace `<`/`>`/control characters in header/`files` before building `text`.

### [low] checkpoint commits do not consult the SensitivePolicy — `crates/titi-cli/src/git_checkpoint.rs:17-40` (vs `crates/titi-tools/src/git.rs:168-172`)
`snapshot` runs a plain `git commit` on the current branch over whatever is
staged, with no `policy.blocks` check, while the `git_commit` tool refuses
credential paths precisely because "a key in the history is worse than a key on
disk" (`git.rs:170-171`). A user who has staged a `.env` gets it committed by a
checkpoint, and a later `git push` publishes it (the module doc's "never pushed"
holds only until the next push).
Fix: skip (or refuse) staged paths `policy.blocks`, or commit to a temp ref.

## Tech debt not worth fixing now

- `HttpRequest` derives `Debug` over raw headers (`titi-providers/src/http.rs:11-16`),
  so a future `{:?}` would print `Authorization: Bearer …`; only tests format it
  today. A manual masking `Debug` would remove the trap.
- No `Zeroize`/`Drop` on any credential string (`titi-providers/src/creds.rs:40-56`,
  `titi-secrets/src/store.rs:97-120`) except the share key
  (`titi-core/src/share.rs:136-141`); tokens live in the heap until GC.
- `memory.embeddingModel` is set (`titi-cli/src/engine.rs:734`) into
  `EngineConfig.embedding_model` (`titi-engine/src/runtime.rs:475`) and never
  read — the index is hardwired to `LocalEmbedder`
  (`titi-memory/src/index.rs:141,232,252`) and `ProvidedVector` is unused, so a
  project-set value cannot send memory to a provider. Dead setting, not a leak.
- `write` is the only content-returning/creating tool without a `policy` field
  (`fs.rs:431-437`) — fine today because writing a secret is not leaking one.

## Unverified: what you could not check and why

- Live provider behaviour: whether a provider echoes a *partial* key in a 4xx
  body. `redact_error_text` (`titi-providers/src/wire.rs:885-900`) only replaces
  the exact full access string, so a partial echo would leak a prefix — needs a
  real endpoint to observe.
- Exact regex-crate semantics: I transcribed `difftrack`/`redact` patterns into
  Python and relied on `\w` including `_` (true for both engines). The audit
  rules forbid running `cargo test`, so this is a transcription, not a run of
  the Rust code.
- The mode of `<agent_dir>/trajectories/<session>.jsonl` on a given machine:
  `trajectory.rs:99-107` sets no mode, so it is whatever umask yields — I did
  not inspect a live file.
- Git's `core.quotePath=true` rendering of a filename containing `</diff>`: I
  reasoned that the bytes appear either quoted or raw; I did not create a repo
  to confirm the exact header (the audit forbids writing git state).
- OAuth token exchange paths (`titi-providers/src/oauth/*`) were only read at
  the seams the secrets scout reported; the browser/device flows were not
  exercised.
